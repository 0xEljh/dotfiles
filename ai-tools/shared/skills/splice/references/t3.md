# Coordinate a Splice run in T3

Use the live tool catalog for schemas and available models.

## Launch workers

Call `orchestrator_capabilities` to select the OpenCode provider instance and
model. Launch each workstream with `delegate_task`, using the
[worker brief](worker-brief.md) as `task`, `isolation: "worktree"`, and normally
`mode: "async"`. Use a stable `clientRequestId` when retrying the same launch.

Managed worktrees start from the coordinator's committed `HEAD`. Uncommitted
changes are not copied. For dependent work, have the worker incorporate the
prerequisite changes before coding and rerun affected setup.

Retain `taskId` for status and cancellation, and `childThreadId` for the worker
link. Read the worker's actual branch and checkout with `t3_thread_read` when
needed, such as when choosing the base for a stacked pull request.

Link workers as `[descriptive title](t3-thread://v1/<childThreadId>)` using the
returned identifier. Keep tool identifiers in tool calls rather than displaying
them as workstream names.

Asynchronous completion wakes the coordinator. End the turn when only outstanding
tasks remain. Use `task_status` during active coordination or resume, not a polling
loop.

## Coordinate dependencies

Check task completion, outstanding child work, and the current pull request head
before releasing dependent work. Match verification and review results to that
head. Have the worker resolve failures or missing checks.

For stacked delivery, give the next worker the predecessor's pushed commit and
actual branch as its pull request base. For work that waits on a merge, confirm
the merge with the hosting service and use a commit containing the merged changes.
Reconcile affected dependencies if the predecessor changes.

## Link pull requests

Workers link pull requests in their threads. The coordinator also calls
`link_pull_request` for every pull request it coordinates, including every layer
of a stack. Before handoff, call `list_thread_pull_requests` and link any that are
missing. Report linking failures.

When monitoring is requested, use `watch_pull_request` and end the turn. Reconcile
the hosting service's state on wake. Call `unwatch_pull_request` before handoff.

## Resume or cancel

Resume in the original coordinator thread and reconcile existing tasks before
launching replacements. Managed task ownership belongs to that thread.

Use `task_cancel` to stop owned work, then check that execution and pending child
work have stopped. Worktree deletion is not cancellation.
