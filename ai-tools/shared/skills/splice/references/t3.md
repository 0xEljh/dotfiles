# Coordinate a Splice run in T3

Use the live tool catalog for schemas and available models.

## Launch workers

Call `orchestrator_capabilities` to select the OpenCode provider instance and
model. Launch each workstream with `delegate_task`, using the
[worker brief](worker-brief.md) as `task`, `isolation: "worktree"`, and normally
`mode: "async"`. Use a stable `clientRequestId` when retrying the same launch.

Managed worktrees start from the coordinator's committed `HEAD`. Uncommitted
changes are not copied. Record the starting point. If the coordinator's checkout
changes during the run, reconcile affected plans and worker inputs before launching
more work rather than silently assigning different starting code.

Retain `taskId` for status and cancellation, and `childThreadId` for the worker
link. Read the worker's actual branch and checkout with `t3_thread_read` when
needed. Recheck at handoff and resume; an earlier branch report may be stale.

Link workers as `[descriptive title](t3-thread://v1/<childThreadId>)` using the
returned identifier. Keep tool identifiers in tool calls rather than displaying
them as workstream names.

Asynchronous completion wakes the coordinator. End the turn when only outstanding
tasks remain. Use `task_status` during active coordination or resume, not a polling
loop.

## Coordinate dependencies

Check task completion, outstanding child work, and acceptance evidence before
releasing dependent work. A completed turn alone does not mean the result is ready.
Check that verification and required reviews apply to the delivered result. Have
the worker resolve failures or missing checks. If an earlier output changes,
revisit affected downstream work.

Waiting for a dependency does not transfer its output. Include relevant findings
in the consumer's brief. For files, provide an accessible path or copy them into
the run's artifact directory, and check that the consumer can read the expected
content. Untracked files do not automatically appear in another worktree. Local
handoff copies are task-local work, not external publication.

For code, have the worker commit the intended deliverable changes on its assigned
branch and return the branch and a summary of what is ready. Do not include
unrelated generated files. Check that the branch contains the expected changes
and no deliverable work remains uncommitted before handing it to another worker.
Fetch from the configured repository remote if needed and permitted. If commits
are prohibited, agree on another handoff rather than assuming branch integration.

## Transfer code and integrate

Give dependent workers the prerequisite branch and explain which changes they
need before coding. Fast-forward their assigned branch when possible, then check
that the expected changes are present. Divergence calls for an integration step
or a revised plan, not an implicit reset or rebase.

T3 may run project setup before the worker starts. Before adopting prerequisite
code, establish which setup steps are worktree-local and safe to repeat. Rerun
affected repeatable steps afterward. If setup has uncertain shared side effects,
resolve those before proceeding.

A named integration worker starts from the planned baseline and merges the
contributing branches into its own assigned branch, preserving source branches
and the coordinator's checkout. Resolve conflicts within the producer and
integration scopes. Return wider changes to the coordinator for a scope decision
or producer follow-up. Run the producer checks and cross-component checks named
in the integration brief. Separate worker checks do not verify the combined result.
Return the final branch, checks and results, and any remaining blockers.

## Keep a run record

Keep a coordinator-owned Markdown record in a unique run directory under
`<git-common-dir>/splice/`, resolving the common directory through Git. Record the
owning thread, plan, delivery policy, concurrency, starting point, worker branches,
outputs, status, and verification results. Save launch request identities before
calling the tool, then record returned task and thread identities. Keep secrets
out of the record. Workers return results through managed completion and
`task_status`, rather than editing shared bookkeeping.

## Resume or cancel

Resume in the original coordinator thread and reconcile existing tasks, outputs,
and workspace bindings before launching more work. Managed task ownership belongs
to that thread. Reuse the saved request identity when retrying an uncertain launch;
do not create a replacement while the original work may still be running.

Use `task_cancel` to stop owned work, then check that execution and pending child
work have stopped. Worktree deletion is not cancellation.

Retain worktrees, run records, and artifact copies until cleanup is requested.
